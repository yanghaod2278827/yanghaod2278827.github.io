我一直在用 Claude Code 接第三方 API。某天顺手看了一下它自带的花费统计，发现一个很荒谬的事：同一个会话，它说花了 `$45.45`，而实际按服务商官方价目算是 `￥4.66`。

差 69 倍。

## 为什么差这么多

Claude Code 的成本字段是它自己算的。对于它认识的模型（Anthropic 自家的），这个数字是准的；对于不认识的第三方模型，它会拿 Claude 的价格去套——一个几块钱的模型被按旗舰价格计价，就差出了两个数量级。

这件事的麻烦之处在于：**它不报错**。数字看着很像真的，你不会怀疑，直到某天去对账单。

## 还有一个更隐蔽的错

写的时候翻了 Claude Code 的转录文件，发现它对同一个响应会**按 content block 分行写入**——thinking 一行、text 一行、tool_use 一行，每行的 `usage` 字段完全相同。

任何按行统计 token 的工具，都会虚高大约 2.4 倍。市面上几个流行的统计工具都在踩这个坑。

## 所以写了这个

[claude-statusline](https://github.com/yanghaod2278827/claude-statusline) 做三件事：

1. **按 `message.id` 去重**，一个响应只计一次
2. **逐请求按当时费率计价**——同一会话里 09:59 和 10:01 发起的请求，按不同价格算
3. **余额跟着花费同帧变化**，而不是每两分钟才跳一次

顺带把峰谷价、法定节假日、缓存命中率也做了。

## 一点感想

写完之后看了一圈同类项目，发现这个方向已经有人做过，而且有的做得比我全。但我不后悔——因为**写的过程本身就是把「数字为什么错」这件事想清楚的过程**，这比多一个工具值钱。

如果你也在用第三方 API 跑 Claude Code，装之前先确认一件事：你的服务商真实价目是多少。网上流传的大模型价格表里，有相当一部分是错的。
