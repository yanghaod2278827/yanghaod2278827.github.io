用本地 ASR 转写一段讲座录音，热词表里放了领域词汇。转写出来的数字看着完全正常——句子通顺、语法对、上下文也搭——但**金额错了**，错到足以让人得出"对方自相矛盾"的结论。

问题不在识别失败，而在识别"太成功"：热词把同音候选拉向了热词表里的邻居。

## 现象

热词表里有「八十万」这类词时，录音里实际说的**二十万**会被识别成八十万。两者声母韵母相近，在有 context bias 的解码里，热词先验足以翻盘。

危险之处在于它**没有任何信号**：

- 不报错、不警告；
- 输出读起来比错误还顺——"八十万"配上后面的数字，能推出一整套自洽但完全错误的账；
- 小模型尤其明显，大模型也不是免疫。

## 为什么"读起来顺"反而是坏消息

静默失败的一般形态是"少了东西"，而这里错的是**内容本身**。你拿它去做判断，得到的是一个**看起来有逻辑的结论**，比直接乱码更难发现——乱码你会去查，通顺的错误你会直接采信。

## 核验流程

对任何要进决策的数字（金额、年限、届别、名额、日期），走三步：

```bash
# 1. 用字级时间戳定位含目标数字的片段
grep -n "八十" transcript.srt        # 找到大致位置

# 2. 切出 15–45 秒，保留上下文但不引入无关噪声
ffmpeg -ss 00:12:30 -to 00:12:58 -i audio.wav clip.wav

# 3. 同一模型去掉热词重跑
python transcribe.py clip.wav --no-hotwords
```

再换一个**异构引擎**跑同一段（比如 Qwen3-ASR 对 SenseVoice，或对 Paraformer）。异构的意思是模型架构和解码策略不同，不是同一个模型的两个尺寸。

**只采信两个引擎一致的结果**；不一致的标"存疑"，不要二选一硬猜——两边各错一次的概率不低，但你至少知道这里不能下结论。

## 还有最后一层

就算两个引擎都说是二十万，那仍然是**一次口述**。口头给的条件会有口误、有补丁、有"我说的是税前"。决策级的数字最终要以书面材料为准，ASR 只负责帮你**定位到该看哪一句**。

## 判据

> 一个数字只有一个引擎背书，就等于没有验证。

热词不是免费的准确率——它是用"往热词表靠"换来的识别率。凡是热词表里含数字的场合，都要把这一步的代价算进去。
